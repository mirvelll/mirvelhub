# MIRVEL HUB

Личный сайт-коллекция: CD, винил, игры, вещи (stuff), вишлисты, тир-листы, ачивки, аналитика. Чистый HTML + CSS + JS, без сборки и сервера — открывается как статический сайт. Данные лежат в браузере (IndexedDB, запасной режим localStorage) и входят в бэкап `.json`.

Интерфейс на русском (есть переключение RU / EN / UK через словарь, см. ниже).

## ⚠️ ПРАВИЛА ДЛЯ НЕЙРОСЕТИ — прочитай до начала работы

Эти правила выполняются при КАЖДОМ обновлении, даже если пользователь о них не напоминает.

### 1. Повышай версию сайта
В левом нижнем углу сайта висит метка версии (`v20.xx`). После каждого обновления её нужно повысить на `0.01` (20.35 → 20.36, 20.99 → 21.00). Одна порция правок = один раз `+0.01`.

Где менять (всё одним числом):
1. `js/00-storage.js` → `const BUILD = '…';` (из неё берётся метка в углу и `?v=` у всех js-файлов).
2. `index.html` → `<script src="js/00-storage.js?v=…">` — то же число.
3. `index.html` → если правил CSS-файл, у его `<link href="css/….css?v=…">` тоже поставь то же число.
4. Если создал НОВЫЙ js-файл — добавь его имя в массив `SCRIPTS` в `js/00-storage.js` (в нужное место порядка загрузки), иначе он не подключится.

Без повышения правки могут не дойти до браузера из-за кэша.

### 2. Что отдавать пользователю после работы
Всегда ДВА архива (zip):
- **полный сайт** целиком (`mirvelhub-main-v20.xx.zip`, внутри папка `mirvelhub-main/`);
- **только изменённые файлы** (`changed-files-v20.xx.zip`) с теми же путями папок, что и на сайте — чтобы пользователь заменил только их. Сравнивай с тем архивом, который пользователь прислал в начале (`diff -rq`), и клади в архив все отличающиеся файлы, включая `index.html` и `js/00-storage.js` (версия).

Если пользователь просит «только новое» — отдавай только архив изменённых файлов. Между обновлениями он сам заливает файлы на хостинг, поэтому в изменённые файлы должны входить ВСЕ правки с прошлых раундов, которые он ещё не залил (если сказано, что не заливал — считай от исходного архива).

### 3. В конце ответа
Напиши «Версия сайта: v…» и коротко (по пунктам) что изменилось — пользователь проверяет сайт и потом пишет, что сломалось.

### 4. Стиль работы
- Пользователь пишет голосом/разговорно, нечётко — вычленяй задачу, а идеи предлагай коротко и отдельно; лишнего без просьбы не добавляй.
- Не ломай существующие данные: новые поля пользовательских данных добавляй необязательными (старые записи без них должны работать), миграции — одноразовые, с флагом в `data`.
- Не переписывай файл целиком ради маленькой правки; правь точечно.
- Проверяй результат в браузере (Playwright/Chromium): открыть страницу, прокликать новую функцию, убедиться, что в консоли нет ошибок.

## Структура

```
index.html          — разметка всех страниц (одна HTML-страница, страницы переключаются JS)
css/                — стили (style, polish, games, hub2, settings, features, wishlist, achievements, tailwind, motion)
js/                 — модули с номерами; порядок загрузки задан в js/00-storage.js → SCRIPTS
```

Загрузка: `index.html` подключает только `js/00-storage.js`, а тот сам подтягивает остальные модули по массиву `SCRIPTS` (preload параллельно, выполнение строго по порядку, `?v=BUILD`). Он же открывает IndexedDB, читает данные и ведёт журнал/бэкапы.

Главный глобальный объект данных — `data` (`data.cds`, `data.vinyls`, `data.games`, `data.stuff`, `data.wishlists`, `data.prompts`, настройки и т. п.). Сохранение — `save()` (с перерисовкой) или `persistData()` (только запись). Экранирование HTML — `esc()`, тосты — `showToast(msg, type)`.

### Ключевые модули (js/)
| Файл | Что внутри |
|---|---|
| `00-storage.js` | загрузчик, `BUILD`, `SCRIPTS`, IndexedDB, бэкапы |
| `08-core.js` | форма добавления/правки CD, винила и др. (`openModal`, `saveItem`) |
| `11-render.js` | отрисовка карточек и сеток, поиск и фильтры внутри страницы |
| `12-app.js` | навигация, Ctrl+K (палитра команд и поиск по коллекции) |
| `16-games.js` | страница игры (детали, фото, заметки) |
| `20-music-detail.js` | страница релиза CD/винила: заметки, **трек-лист с оценками**, «Об издании», фото; карточка «Поделиться» (1080×1920) |
| `36-tierlist.js` | тир-листы |
| `47-prompts.js` | вкладка «📝 Промпты» в настройках (группы, встроенные промпты) |
| `i18n-dict.js` / `i18n.js` | словарь и движок перевода RU / EN / UK |

## Данные релиза (CD / винил)

Кроме базовых полей (`title, artist, price, year, label, condition, formatDetails, rating, note, img, photos[]…`):

- `tracks[]` — трек-лист: `{ id, t, d, r, f }` — название, длительность `М:СС`, оценка 0–5, любимый (♥). Секция (Сторона B / Диск 2): `{ id, sep: true, t }`.
- `phys{}` — «Об издании»: `cat` (номер по каталогу), `bar` (штрихкод), `country`, `num` (номер экземпляра/тираж), `sleeve` (состояние конверта), `sealed`, `signed`, `ltd`.

Формат «Вставить списком» для треков: одна строка = трек (`1. Название 3:45`), строка `# Сторона B` — секция. Тот же формат выдаёт встроенный промпт «Трек-лист альбома».

Поиск по названиям треков работает и на страницах CD/винила (`11-render.js`), и в Ctrl+K (`12-app.js`, функция `trackHit`).

## Промпты (настройки → «📝 Промпты»)

`data.prompts = [{ id, title, text, group }]`. Промпты разложены по группам (`group`: «Ачивки», «Музыка», «Для сайта», свои; без группы — «Без группы»). Встроенные промпты добавляются одноразовыми миграциями с флагами `data.promptsV2…V5` — удалённый пользователем промпт не возвращается, его правки не затираются. Новый встроенный промпт = новая функция `upgradeN()` + свой флаг.

## Переводы

Новая русская строка в интерфейсе → добавь строку в `js/i18n-dict.js` в виде `["русский", "English", "Українська"]`. Подстановки: `{0}`, `{1}`. Проверка пропусков в консоли браузера: `MirvelI18n.report()`.

## Проверка перед отдачей

1. `node --check js/<файл>.js` для каждого изменённого js.
2. Открыть сайт локально (`python3 -m http.server`), прокликать новое, посмотреть консоль.
3. Убедиться, что метка версии в углу показывает новое число.
4. Собрать оба архива (см. выше).
